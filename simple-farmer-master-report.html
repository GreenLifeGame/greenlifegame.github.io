01

Executive Summary

Simple Farmer is a Solana-themed play-to-earn crop-farming web game — the second title on the GreenLifeGame (GLG) platform, and deliberately the simpler/easier one. Where GREEN LIFE is a deep cannabis-farming economy with Mythical breeding, a 3D world, PvP games, tournaments, weapons/defend, clans and a 22,000-line codebase, Simple Farmer strips the same core shape (buy a farm, plant cards, earn a token, breed, trade, refer friends) down to fewer systems and a flatter, more approachable economy — fruits and vegetables instead of strains, a 5-tier rarity ladder with no Mythical ceiling, and an overhead SVG farm map instead of a walkable 3D room.

Current build status: the game is a fully simulated client-side prototype. The landing screen states this outright — "The wallet is simulated — nothing connects to Solana and no signature in this build is real." Every balance, purchase, harvest, breed and claim happens as in-memory React state; nothing persists past a page refresh, and no real money moves anywhere in this codebase today.

Core game loop

Connect wallet (simulated)→ Invite code (roulette matches you if you have none)→ $25 buy-in, SOL/USDC/USDT→ Farm mints + $5 $GREEN bonus + 1 Starter Pack auto-opens→ Plant & earn every second→ Rip packs / crossbreed / boost→ Level the farm / unlock plots→ Trade / refer / play the lottery / repeat

Navigation is a bottom bar of six tabs plus a conditional seventh: Farm · Garden · Breed · Market · Stuff · World — and, when the (currently wide-open) admin flag is set, a seventh 🛠 Admin tab. Market is its own full tab here — unlike GREEN LIFE, where Market is a block inside World; Simple Farmer's World screen instead holds the shared emissions pool, a simulated leaderboard, a pool-life decay projection, and the honest simulated-systems disclosure list (§19, §25).

What makes it "the simple one" — the deliberate simplifications vs. GREEN LIFE

  • No Mythical tier. Legendary is the ceiling, full stop — five rarities (Common → Legendary), not six.
  • One card per pack, always — a Seed/Mystery/Boost/Starter/PRIMO pull is exactly one card, never a multi-card bundle, so a tier's stated odds are literally the odds of that one pull.
  • No watering mechanic. Plants grow purely on elapsed time; there is no Water All button and nothing dehydrates.
  • No 3D room. The farm is a single inline SVG overhead map — deliberately not Three.js, no textures, no draw-call budget to manage (see §22).
  • No PvP games, no tournaments, no weapons/Defend, no clans, no emote system. None of these systems exist in Simple Farmer's current build — a control for a system that isn't there would be worse than no control.
  • A category-gated breeding rule with a real category exclusivity (Veggie×Veggie or Fruit×Fruit only, never across) that GREEN LIFE's breeding does not have.
  • A genuinely different in-tier pack-odds mechanic — value-inverse weighting (cheaper card = more likely) rather than GREEN LIFE's flat 60/30/10 split (see §07).

Relationship to GREEN LIFE & the GLG Platform

GreenLifeGame (GLG) is the shared platform brand across every GLG title. Simple Farmer is one of four confirmed real games under it (GREEN LIFE, the cannabis-farming game; Dino Island; and Mother Lode); the platform's supply plan reserves an emissions pool for each of the four.

The one and only thing shared between games GLG games share ONLY the $GREEN token and its liquidity pool — never code, never a repo, never mechanics. Simple Farmer is its own file set (farmer-*.jsx/farmer-*.js), its own React entry point (farmer-main.jsx mounting into farmer.html), and imports nothing from GREEN LIFE's constants.js/green-game.jsx. The reverse is also true. This is stated as a deliberate isolation choice — reusing GREEN LIFE's UI file, for example, would pull in strain art and weapon tables and "tie the two games together at the code level for no benefit."

Why the pool sizing matters mechanically

"the goal is for all 3 games to have similar earning power, the more advanced games will earn a little more bc it has a higher emission pool and take more player time to play." — Cody, 2026-08-18

The four games split into two tiers, and the rate is paired to the pool size on purpose. Simple Farmer and Mother Lode each run a 200B pool decaying at 0.05%/day; GREEN LIFE and Dino Island each run a 250B pool decaying at 0.069%/day. That works out to roughly 100M $GREEN/day emitted by each of the lighter games against roughly 172.5M/day by each of the heavier ones — a player holding the same share of Simple Farmer's own network earns at about a 1 : 1.73 ratio versus the same share in GREEN LIFE or Dino Island. That gap is deliberate, not a tuning artifact: Cody's call was that "green life and dino island will earn more i know that, and i did it on purpose as it takes more time to play that game." The consequence worth holding onto: earning power is set by pool size, not by Simple Farmer's own crop numbers — making crops more powerful across the board does not increase real payout, because emissions split by share of network power, and raising everyone's power raises the denominator too. The only levers that move real earnings here are the pool allocation and the decay rate.

Platform-shared presentation

  • Both games open on an identical GLG platform splash (GlgIntro in Simple Farmer, its own separate component from GREEN LIFE's equivalent — components are never shared, only art and copy) — same wordmark, same copy: "FIXED SUPPLY · ZERO INFLATION · P2E ON SOLANA" / "1T · MINTED ONCE · NEVER AGAIN" / "tap to enter." Cody's own framing: "this should be the exact intro on all games, the words should match also" — these are platform-wide $GREEN facts, not game-specific ones, so they read identically everywhere.
  • Only the game's own icon art (/glg-brand/glg-icon.png) is shared between the two splashes — same category as sharing the token itself.
  • Simple Farmer's own brand accent color, #52e300, is the exact same green GREEN LIFE uses as its own accent — pulled from the same GLG-family logo palette.

Deliberately separate, and why

  • Separate referral graphs. Each game runs its own 3-level referral chain, its own bootstrap wallets, its own roulette pool. A friend referred in one game is not automatically connected in the other.
  • Separate asset folders. Boost card art lives at public/farmer-boosts/, deliberately not GREEN LIFE's public/boosts/ — the two folders sharing a similar name nearly caused Simple Farmer's renders to save into GREEN LIFE's own asset directory during production; the source explicitly warns never to merge them back.
  • Separate admin consoles, separate wallets registry, separate SIM_FLAGS list. Nothing about Simple Farmer's Admin Console reads or writes GREEN LIFE's state.
  • Deliberately fewer systems. Simple Farmer is positioned as the platform's Easy difficulty tier; GREEN LIFE carries the deep systems (PvP, tournaments, weapons/Defend, clans, a 3D world). A system missing from Simple Farmer is very often not an oversight — it is the tier boundary doing its job.
Gap in the research The research passes available for this report cover only Simple Farmer's own source files in depth. The platform split (Simple Farmer 200B / Mother Lode 200B / GREEN LIFE 250B / Dino Island 250B, plus the shared 50B LP, 25B treasury and 25B giveaway buckets, out of 1 trillion) comes from the locked platform tokenomics rather than from any of those games' code — no GREEN LIFE or "Dino Island" source file was read as part of producing this document, so anything about those other games beyond what Simple Farmer's own comments state should be treated as Simple Farmer's own understanding of the plan, not independently verified against those games' code.

The "How to Play" modal — 7 steps, every number read live

Every figure in this modal is computed from the actual live constants at render time (never hand-typed) specifically so it can never drift from what the game really charges — though the source itself documents that this exact promise was still caught failing once (a hardcoded currency label slipped through the 2026-08-24 audit; see §26).

1 · Connect & enter
Connect a wallet, enter an invite code, pay the $25.00 entry to mint your Level 1 farm. It opens itself right away.
2 · Plant & earn every second
70% of your farmed $GREEN streams the instant it's earned; the other 30% holds in a pot that only pays out at harvest.
3 · Rip packs
Seed $1.50 · Mystery $1.00 · Boost $0.50 (all $GREEN today) — at the live price and currency, whatever they're currently set to. No daily limit on any of them.
4 · Upgrade
Spend $GREEN to level your farm (Lv2–5, $10.00 flat each): more garden plots, higher pack limits. Each level has its own build-time cooldown.
5 · Emission decay
Every 24 hours the network emits 0.05% of whatever's left in the rewards pool — a slow, sustainable curve instead of a spike.
6 · Burn
Every $GREEN spent in-game is burned forever — never returned to the pool.
7 · Refer & earn
3% of your direct referrals' earnings and pack buys, 1% from their referrals, 0.01% one level deeper. Three levels — that's the cap, always.

Stage 2 — "checking" (the existing-farm lookup)

Roughly a 900ms artificial delay standing in for an on-chain lookup. No buttons on this screen on purpose — nothing has been decided or charged yet. Copy: "Checking your farm… Looking up whether {wallet} already owns one. Connecting your wallet is the login — if you already farm here you go straight in. No code, no second buy-in."

Why there is no "I already have an account" button Connecting the wallet IS the login. A farm lives at an address derived from the wallet itself, so the game just looks: if this wallet owns one, the player is dropped straight back into it, never asked for an invite code, never asked to buy in again. A separate button for "I'm returning" can be tapped wrongly by a new player, and tapping it wrongly could walk an existing owner toward paying the $25 entry a second time.

findExistingFarm() is an explicit stub in this build — it always returns null (gated by a DEMO_EXISTING_FARM testing flag, currently false), so every connect in this build onboards as brand new.

Stage 3 — "invite" (the code screen)

Split into its own screen on 2026-08-24 specifically to mirror GREEN LIFE's own two-screen invite/entry split "screenshot-for-screenshot." This screen's only job is collecting a code — no price, no wallet, no "what you get" belongs here.

  • Entry is invite-only, no skip. Continue is hard-gated on the code being at least 4 characters — a real generated code is 4 letters + 3 digits = 7 characters, but the minimum-to-continue is looser to allow shorter/longer aliases in the future. The field itself accepts up to 12 characters (REF_CODE_MAX_LEN, raised 2026-08-27 to match GREEN LIFE — see §16), room enough for a readable admin-set name, not just the generator's own 7-char shape.
  • Code alphabet: ABCDEFGHJKLMNPQRSTUVWXYZ — I and O deliberately excluded so a code read off a screen can never be confused with 1 and 0.
  • 🎲 Referral roulette shows 5 candidates per click — 2 admin-locked identities that never rotate, plus 3 randomly-rolled real-referral-count candidates the player picks from (never auto-assigned) — the same 5-slot/2-locked pattern ported from GREEN LIFE 2026-08-27; see §16 for the full mechanic. Every candidate resolves to a real, known ancestor, so a brand-new player's referral cut resolves correctly from their very first action.
  • Optional claim code field — if a valid claim code is typed here, it waives the entry fee entirely on the next screen (validated live via checkClaimCode() before the player even continues).

The multiplier math

Locked rule A garden's multiplier scales a planted card's farm power UP by that factor AND divides its harvest cycle DOWN by the same factor. Net effect: a single harvest pays exactly the same total whichever tier it's in — rate doubled while time halved cancels out. The real benefit of a higher tier is THROUGHPUT: over a fixed stretch of real time you finish more cycles, so total earnings scale linearly with the multiplier, not exponentially.

Cody's own words: "if a veggie is 7days 1x on 2x it should be 3.5days and earn the same amount it would from 7 days but in 3.5 days."

Formulas: cycleMs(cropKey, mult) = (CROPS[cropKey].days / mult) × growDayMs(); plantPower(cropKey, mult, boostPct) = CROPS[cropKey].power × mult × (1 + boostPct/100).

Slot ownership & unlocking

  • The 1X Garden auto-unlocks the moment the farm level allows it — no purchase, no button. It is the only tier with solPerSlot === 0, so owned just tracks the level-derived cap directly.
  • Every other tier requires an explicit SOL purchase per plot, one at a time, strictly in order — the game only ever offers the next unbought plot for sale; tapping ahead in the queue is blocked with "take plot N first."
  • Purchases route through the real SOL/USDC/USDT pay-with picker and a wallet-sign screen (fixed in the 2026-08-24 audit — it used to charge SOL directly with no confirmation).
  • The Garden screen renders every plot the tier could ever reach at farm Level 5, not just what's unlocked today — locked cells show what farm level unlocks them and at what price, so a player can see what leveling up actually buys.

Planting — a staged batch that signs once

Cody, 2026-08-24 "when planting cards in the game make sure there is a sign to complete the task at the end they can do multiple in and out but they have to sign to finalize it. that is a final decision. weed game has this but simple farmer needs it."

A card tapped into a plot becomes PENDING — not a real plant, not earning yet — until one signature commits the whole batch. Tapping a pending card again pulls it back out for free, no signature either way; only the final "🔐 Confirm & Sign" commits. The staging bar shows the GLOBAL staged count across every garden tier at once, not just the one currently on screen, since one signature commits all of them together.

Boosts on a growing plant

One active boost per plant, no stacking, no cancelling, no swapping. A boost lasts exactly as long as the plant's own harvest cycle — not a fixed day count, since cycle length itself changes with garden tier. Applying a boost is deliberately not offered on a fully-grown (ready) plant, since a finished plant has already stopped earning and the card would be burned for zero effect.

The emissions engine

emissionDay(pool, rate) = pool × (rate/100); playerPerSecond = emissionSecond × (myEarningPower / totalNetworkPower). Every second, 70% of a player's share streams straight into their claimable balance; the other 30% accrues into each individual growing plant's own pot, split across a player's plants by their relative share of that player's own power. A finished (ready) plant stops earning entirely and is excluded from earning-power calculations — it still counts toward total farm power on the leaderboard, but not toward the emissions share.

Early-pull outcome curve

Fractions of a plant's own cycle — deliberately a percentage, not a fixed day count, because a garden multiplier can shrink a plant's real cycle length by up to 100×; a fixed-day rule would wrongly call a 100X plant "pulled too early" when it had actually finished.

This mirrors GREEN LIFE's locked day-22-of-30 curve, expressed as a fraction so it scales correctly across every garden multiplier. Forfeited pot amounts (from death or penalty) are BURNED, never returned to the emissions pool.

Referral cut on claim/harvest

Only applied when the player was actually referred (referredBy set) — an organic player with no referrer pays nothing extra either way. The cut is 4.01% total, carved out of the player's own payout, same rate as the pack-purchase cut (see §16, §23).

The harvest handler re-verifies its targets against a live ref of current plants before crediting anything, specifically to make a rapid double-click a clean no-op rather than a real double-credit — found and fixed in the 2026-08-24 audit as a real risk, not a hypothetical one.

Two standing prize systems sit stacked on the Farm screen, and despite the similar name they are opposite designs on every axis: GLG Lottery (below) is player-funded and shared cross-game; Simple Farmer Raffle (further below) is entirely GLG/treasury-funded and scoped to this game alone. GLG Lottery — Four Standing Pools

A straight port of GREEN LIFE's 4 standing pools — one panel, a 2×2 grid, sitting on the Farm screen above the pack carousel. Each pool is a weighted raffle: buy tickets, more tickets improve odds, one weighted-random winner takes the whole pot when the clock hits zero, then the pool immediately starts its next round.

The block's own header note was rewritten 2026-08-28 to name all three GLG games directly instead of a hedged "shared with every GLG game" framing: "Each Lottery is shared between all GLG games. (GREEN LIFE's own matching header got the identical rewrite the same session.) The 🧪 SIMULATED disclosure directly underneath is untouched — still the honest fine print about how a draw is actually resolved today, see below.

Fee is 100% treasury, deliberately never burned A flat 5% (LOTTERY_FEE_PCT) is taken from the pot and credited entirely to the treasury, funding future giveaways and events. This is a deliberate exception to the game's otherwise burn-heavy spend model: a lottery ticket is a wager pooled between players and redistributed, the same shape as any other PvP-style ante — not a spend that consumes an item, so it doesn't burn like one.

As of 2026-08-28 a bonus top-up also registers with the real cross-game server ledger (glgServerAddBonus) alongside the local pool, matching how a ticket purchase now registers server-side too (below).

Three reasons it's deliberately not 3D

  1. GREEN LIFE's 3D room is the single heaviest thing in that codebase (draw calls, textures, shadow maps, a whole documented lag-fix history) — a picture that costs nothing to render keeps Simple Farmer the genuinely simple game.
  2. An SVG scales to any phone with no art pipeline and no asset loading — nothing to go missing, nothing to wait on.
  3. Every number on it is read live from game state, so the picture can never drift out of step with reality the way a pre-made image would.

What's real vs. what's pure decoration

The five garden patches, their plot dots, and the plants in them are REAL — sourced directly from live game state and updated as the player plays. The barn, farmhouse, dirt path, sun and clouds are pure decoration — no mechanics behind them at all, nothing to click, nothing to buy, nothing to upgrade. They exist purely so the screen reads as a farm and not a chart.

Each garden patch is drawn at a fixed layout position, keyed by tier id (not list order), so an unreachable/reordered tier is simply skipped rather than silently drawn on top of another one. Plots pack into a grid sized to fit the patch, with the last row centered rather than left-hugging. Toxic Area gets a distinct pulsing sickly glow and diagonal hazard-stripe border, since it is one plot at 100× power and should visually read as the dangerous corner of the farm.

A planted crop's emoji physically grows in size as it matures (from ~1.05× to ~1.6× the plot's own dot radius) — "the fastest way to read a whole field at a glance without putting a number on every plot." A ready-to-harvest plot gets a pulsing gold ring and switches its fill/border to gold, so finished plants are findable without reading anything.

Empty-state routing (4 distinct branches)

The scene picks its empty-state message and call-to-action based on exactly why the farm is empty — not a generic "plant something": no plots owned yet routes to the Garden; plots owned but a card in hand routes to the Garden; plots owned but everything is still sealed in a pack routes to My Stuff; a genuine fallback (nothing owned, nothing in hand) points at the pack carousel. This exists specifically because a brand-new player's first card is locked inside the sealed Starter Pack — sending them straight to an empty Garden with an empty inventory would be a dead end.

Harvest/Plant/Boost action row — removed 2026-08-27

Cody's original spec for this screen (quoted above) called for "action abilities like harvest, plant, boost" directly on the map, and an early build did carry a row of the three. It came out once it was actually redundant: Plant and Boost were pure goGarden() navigation shortcuts with no action of their own, and Harvest duplicated the Garden screen's own per-tier "Harvest ready" button exactly. Cody reported the row "felt like it did nothing" — removed entirely rather than fixed, since there was no real action left for it to perform. Tapping a garden patch on the map still navigates to the Garden screen; harvesting now only happens from the Garden screen's own tabs.

The marketplace's 5%-burn half was never actually implemented — fixed 2026-08-31

Found while re-verifying the ALREADY-locked 90/5/5 marketplace split against Cody's sheet (it wasn't a new rule — the sign sheet, the constants file's own comment, and this very report all already said "5% burn + 5% treasury"). The code that resolves a real listing sale funneled the FULL 10% fee into treasurySol, with a comment claiming it was "the same combined burn+treasury bucket" — nothing was ever actually burned. Fixed to genuinely split: the 5% burn half buys $GREEN from the LP with that SOL (same market-buy mechanic the $5 sign-up bonus already uses) and burns the resulting $GREEN; the 5% treasury half is unchanged.

The NPC-seeded-listing buy path got the same fix, one directive later. buyListing/buyListingBatch (buying from the simulated shop pool, not a real player's own listing) originally routed its whole 10% to treasury on the theory that "no real seller" meant nothing to split — that theory held for the 90% seller share (still true: there's genuinely no one to pay it to) but not for the burn half, which needs no counterparty at all. Cody's call once this ambiguity was raised: "this should be built for the 5% buyback and burn, 90% to seller, remaining 5%ish treasury." Both functions now credit the same real 5%/5% split as every real-seller path; the sign-sheet copy on both was updated to say "simulated seller, no 90% to split" so the remaining asymmetry (only the seller's share is unpayable) stays honest rather than implying the whole fee is inert.

Where the referral cut actually goes when it can't be paid

In this single-device simulation, a cut owed to a real (non-bootstrap) referrer has nobody live to pay — it accumulates in refChainPayout, an honestly-tracked running total, rather than being silently dropped or wrongly credited to the paying player's own referral-earnings pot (a different pot entirely — that one is what a player earns as a referrer, not what they pay as someone who was referred). Any portion of the cut that resolves all the way up to the bootstrap chain's burn seed is destroyed for real, immediately, regardless of backend status. This applies identically whether the cut originated from a $GREEN spend or a SOL spend's new refCut mode — both route through the exact same chain-split logic.

Burn sources, consolidated

  • $GREEN pack purchases, incl. PRIMO (remainder after the referral cut)
  • Crossbreeding (100%, no cut)
  • Farm-level upgrades, plot upgrades, Toxic Garden, Season Pass Premium, Raffle tickets — all when paid in $GREEN (100%, no cut)
  • Forfeited harvest pots (a plant that died or was penalized) — burned, never returned to the pool
  • The referral cut's own portion that reaches the bootstrap chain's burn seed, on either a $GREEN or SOL spend
  • The marketplace fee's 5% buyback-burn half — on a real listing sale AND on an NPC-seeded-pool buy alike (see above — newly real this pass, both paths)

What is NOT burned

  • Any SOL-priced purchase that isn't one of the above $GREEN paths — routed to the LP/treasury split, or 100% treasury for the treasury-only items
  • The GLG Lottery fee — 100% treasury, a deliberate exception (§15)
  • The marketplace fee's 5% treasury share (real, by design — never meant to burn)

Issues the game's own source explicitly flags as unresolved, plus gaps in the research this report is honest about rather than papering over.

PRIMO's Legendary rate vs. this game's thin Legendary roster 25% Legendary on PRIMO was ported directly from GREEN LIFE for parity, but Simple Farmer has only two Legendary crops total. One crate a day at 25% mints Legendaries far faster than the base pack's 0.5% rate — explicitly flagged in the source as an easy dial to turn down, not yet turned.
The marketplace's own buyer sign-sheet vs. its fee panel disagree on the current split The buy-side wallet-sign screen states the entire 10% fee books to treasury today; the fee panel elsewhere on the same screen still shows the target 90/5/5 breakdown. WORLD_RANKINGS (farmer-constants.js) is the registry — 6 entries, each {id, emoji, label, desc}, plus rankingById(). rankingLiveValues (a useMemo in farmer-game.jsx) combines all 6 into one object every render, the single source both the World screen and the admin panel read from.

A real gap this closed: Marketplace listings could never actually sell

Market Mogul needed a real "you sold something" event to track — and the game's own listings had none. listingSellTickPct(tickMs) gives every open listing an independent per-tick chance of selling, calibrated so a listing has roughly a 65% chance of selling within its full TTL window (LISTING_SELL_TARGET_PCT = 0.65) rather than either never selling or resolving instantly: 1 − (1 − TARGET)^(tickMs / LISTING_TTL_MS), a constant-hazard-rate model — same shape a radioactive-decay half-life uses. Runs on the game's existing 1-second clock tick (CLOCK_TICK_MS, a new shared constant so the sale-roll and the clock interval can never drift out of calibration with each other). A sold listing pays the seller their net (after the standard marketplace fee), credits the fee to the treasury, and adds the net amount to lifetimeMarketSol — the exact figure Market Mogul ranks on.

Event windows — separate from lifetime totals, admin-controlled, multi-select

Cody's spec, verbatim: "make sure to have a way to keep it seperate from the game totals. if a even starts i should be able to chose to reset the counter for the time of the even. so that way new players can compete with players 3 months old" — then, mid-build: "make sure i can do multiple at a time, like doing rarest collection and marketplace mogul would be win/win for both sides if played at same time."

RANKING_EVENTS holds one {active, startedAt, name} slot per category, not one shared "current event" slot — this is what makes independently-timed, independently-named simultaneous events possible, rather than only one event running at a time across the whole board set. A new admin panel, RankingsEventsPanel (Admin → 🏆 Rankings tab), presents all 6 categories as a checklist with one shared optional event name (e.g. "Collector's Weekend"), and one sign-and-apply action starts or resets every checked category at once with the same startedAt timestamp.

Each player's own event-window score is computed entirely client-side, never server-tracked: the first moment a player's client notices a category's startedAt has changed, it captures a baseline (eventBaselines state) — "my lifetime value right now." From then on, that category's event score is current lifetime value − baseline value, so a 3-month veteran and a brand-new player both start an event at exactly zero, regardless of their lifetime totals. Lifetime boards are never touched by an event starting, resetting, or ending. The World screen shows a 🔥 EVENT LIVE panel above a category's regular lifetime board whenever that category has a live, baseline-matched event running, using fmtDurShort for the "started N ago" line (an earlier draft used fmtDur, which returns the misleading string "ready" for an elapsed time of zero — caught and fixed before shipping since a just-started event would have read as "Started ready ago").

Simulated boards, real player row

Each board's rival rows are simulated (LIFETIME_CACHE/EVENT_CACHE, generic caches keyed per-category so all 6 boards reuse one mechanism instead of six copies of the old single-board code) — no ranking backend exists yet. The event-scoped cache is additionally keyed by ${categoryId}:${startedAt}, so an admin reset naturally produces a fresh simulated field rather than needing an explicit cache-clear step. The player's own row is always their real, live value on every board, event or lifetime.

Scope note — no prize payouts

This build is rankings and visibility only. No prize-payout or reward-distribution system was built for ranking events — a category leaderboard shows standing, nothing more; anything that pays out the top of a board on event-end would be a separate, not-yet-scoped feature.
